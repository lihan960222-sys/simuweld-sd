# sfMarc Workbench 设计

日期：2026-10-26

状态：用户已批准实施及载荷编辑所需的代码。

## 使用目标

用户在自己的 Windows 电脑上打开 sfMarc `.dat` 文件，查看有限元网格，按照相邻面的夹角选择连续表面，设置均布压力或指定方向的均布面力，导出增加载荷后的求解输入。源文件始终保留。项目具备可运行的源码、测试、使用说明和 GitHub 维护配置。

## 已确认的条件与实现方式

用户已选择本机处理，模型文件不上传。采用本机网页与 Python 本地服务，双击启动程序后打开浏览器。Python 负责文件、网格与载荷处理，TypeScript 和 Three.js 负责交互界面。全部页面资源随程序提供，运行时无需访问外部网站。

本地服务仅监听 `127.0.0.1`，使用每次启动生成的访问凭据，检查请求来源。文件访问限于用户主动打开的文件及选择的模型目录。程序不包含远程上传、统计或遥测功能。

交付包含可运行的本机程序、完整源码和可重复执行的 Windows 打包配置。GitHub 项目仅包含程序、文档和具有分发许可的测试资源。用户的模型、材料文件与计算结果保持在本机。

## 操作流程

1. 选择模型文件；存在 INCLUDE 时，同时选择包含相关文件的模型目录。
2. 显示节点、单元和实体数量，以及读取检查结果。显示模型坐标单位与压力输入单位；单位无法可靠识别时要求用户选择。
3. 在三维视图中旋转、平移、缩放，按照实体显示或隐藏模型，切换网格边线。
4. 点击一个外表面，按相邻面法向夹角连续扩展选择。角度可调整，提供增加选择、移除选择和清空选择。
5. 输入正数载荷大小，选择向内、向外或手动方向。手动方向使用全局坐标中的 X、Y、Z 分量，程序归一化方向向量，拒绝零向量。
6. 显示已选面积、面数、方向箭头和预计合力。选定载荷作用的计算阶段，支持选择全部计算阶段或指定阶段。
7. 将当前选择保存为载荷项。允许多个载荷项，能够修改或删除；重叠区域的载荷按照求和处理并显示结果。
8. 导出新 `.dat` 文件及修改清单。导出文件名与源文件区分，源文件不覆盖。

## 网格与选面

使用第三方 `meshioplusplus` 读取 Marc 节点、单元和集合。固定经实际测试的依赖版本。原始单元编号、节点编号与局部连接关系必须保留，不能使用网格转换后的顺序代替 Marc 编号。

当前用户文件包含 163,924 个节点、88,452 个 type 7 单元，以及通过重复节点表示的退化单元。需要以这一真实文件作为完整验收对象，退化单元也必须正确处理。

从原始连接关系计算外表面；相邻关系以共享边的节点编号确定。不同实体中坐标重合的节点不合并。角度选择仅沿当前实体的连续外表面扩展，隐藏实体不参与选择。实体无法从集合中唯一识别时，使用网格连通分量并显示其名称。

显示三角形仅用于绘制与点击定位。载荷始终对应原始单元及其 Marc 局部面号。退化单元先排除零面积面，再建立显示面与原始面号的映射。法向通过面几何与单元内部方向确定；不能可靠判定方向、面发生自交或网格关系不一致时，停止相关载荷的导出并指出单元编号。

相邻面夹角控制连续区域的扩展。曲面可以选择为多个面组成的区域；向内或向外分别使用各个面的法向。载荷预览与面积计算使用原始单元表面，四节点面采用与其形函数相容的数值积分。

## 载荷与求解语义

沿法向的载荷采用 Marc `DIST LOADS` 中的 normal pressure。手动方向采用 general traction，将输入大小与归一化后的方向相乘得到三个面力分量。面力以力除以面积计量，不转换为简单平均分配的节点集中力。

用户选择压力单位与模型单位后，程序完成单位换算，模型坐标不缩放。预计合力通过所选面的积分获得。

使用 TABLE 形式的命名载荷，并在用户指定的 LOADCASE 中启用。保留原有温度、热源、约束等全部标签。界面默认采用阶段内恒定载荷，明确显示起止阶段。

正常压力是否随变形更新由原文件的 `FOLLOW FOR` 设置决定。界面显示当前设置；原文件的这一全局设置不会在导出时静默修改。指定全局方向的载荷需要核对其在该设置下的方向和面积定义。对尚未验证的设置组合停止导出，给出具体原因。

## 保留原文件

`meshioplusplus` 的 Marc 读取器覆盖网格与集合，不读取 LOADCASE、材料和边界条件。其 writer 生成网格输入，不能用于重写完整 sfMarc 文件。

完整导出需要一个范围受限的编辑模块：识别参数段和模型段结束位置，读取 LOADCASE 的名称、标签数量与标签列表，在原字节内容上插入载荷定义，并更新选定阶段的标签数量与列表。其他数据保留原始字节、编码、换行、编号与顺序。

用户已允许编写范围受限的载荷编辑模块。网格解析仍然使用第三方库。编辑范围仅涵盖本功能必须处理的段落与字段。新增卡片依据 Marc 手册生成，数值字段采用现成的 Fortran 格式库。修改清单记录源文件摘要、新增载荷、原始单元面号及受影响的阶段；导出结果重新读取并检查。

INCLUDE 文件只从用户选定的模型目录读取，检查缺失文件、循环引用与目录越界。导出时保持相对目录关系，生成独立的输出文件组。原文件引用的外部材料文件保持原引用；缺失材料文件会在导出清单中明确显示。

## 项目组织

Python 模块分别负责模型读取、表面几何、载荷计算、文件编辑和本地服务。前端分别负责三维视图、选面状态和载荷表单。模块之间传递明确的模型编号、面编号与载荷数据，新增二开功能可以复用现有模块。

仓库提供依赖版本、启动说明、测试命令、Windows 打包配置、GitHub Actions 检查、贡献说明和第三方许可。用户模型与运行中产生的文件加入忽略规则。暂定项目名称为 `sfmarc-workbench`；GitHub 账户与仓库公开范围在发布时确定。

## 验证要求

- 对用户实际文件核对节点数、单元数、原始编号、退化单元与集合，验证选面和载荷导出覆盖该模型。
- 使用真实 Mentat 输入文件核对标准 Marc 格式，记录来源与许可。
- 对实际网格检查内表面消除、不同实体的隔离、连续选面、角度阈值、法向、面积与合力守恒。
- 验证向内与向外的结果互为相反数；验证手动方向的合力与载荷大小、面积及方向相符。
- 对导出前后进行逐字节检查，确保变化只发生在批准的载荷定义和阶段标签位置；检查标签数量、引用、字段宽度、单位与面号。
- 在实际浏览器中执行导入、点击选择、编辑载荷、导出与重新导入，检查应用错误和网络请求。按用户要求不使用截图判断结果。
- 验证本地运行无需远程服务，检查程序仅监听本机地址，并检验打包后的启动过程。

当前未找到可执行的 Marc/sfMarc 求解环境。程序和输入格式检查可以在本机执行；求解器对新增载荷的接受情况、反力与变形结果需要有许可的求解器验证。未执行求解器前，发布状态必须明确标注这一限制。
