# 可覆盖功能目录实施计划

目标：离线电脑关闭 SD 后，覆盖单个业务模块目录即可更新该模块的界面、API、处理代码和脚本模板。

目录为 shared 与 modules/{face_load,weld_paths,thermal_cycle,local_trial}。基础 EXE 提供 Python 与依赖，启动时按清单加载外部代码。清单明确列出文件、版本、接口版本和摘要；只加载列出的文件。用户模型与输出继续存放在这些目录之外。

- 网页：提取面载荷功能到独立文件，业务模块使用稳定的 JS/CSS 路径；公共视窗和第三方依赖放 shared。保留现有界面和交互。
- API：业务路由及请求结构归属各业务模块，公共模型状态与认证由 shared 提供。维持现有 URL、模型身份和并发校验。
- 加载：标准库外部模块加载器依据文件清单加载，验证接口版本、完整性和路径；缺失或不兼容时给出明确错误并停止。
- 交付：生成共享目录、四个独立业务目录、完整包，以及各模块单独 ZIP。模块 ZIP 解压覆盖软件根目录中的同名目录。
- 验证：真实 C0002 网格和局部焊路导出、面载荷与热循环现有测试、浏览器模块切换；对打包程序执行实际目录覆盖并重新启动，验证新模块及未改动模块可用；验证旧文件残留不被加载。

修改源文件使用 apply_patch；构建脚本只负责构建产物的复制、清单和打包。此次不上传 GitHub、不清理历史版本。
